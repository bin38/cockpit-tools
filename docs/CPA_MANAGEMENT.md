# CPA 服务器与凭据管理

入口：**Codex → 账号总览 → CPA 管理**。不改变原有 CPA 文件导出。

## 配置自己的服务器

填写 CPA 服务根地址（例如 `https://cpa.example.com`，支持反向代理路径前缀）和 **Management Key**，不是模型调用 API Key。可指定 v8 / v0，或自动检测（仅 GET 请求，v8 返回 404 才尝试 v0；鉴权失败不降级、不重试）。远程要求 HTTPS 和 CPA 远程管理权限；仅回环地址允许 HTTP。请求不跟随重定向，不关闭 TLS 校验。

第一版支持一个活动服务器。切换已有绑定的服务器前先移除连接；移除连接只停止同步、移除本地管理密钥，不删除远程凭据或本地账号。

管理密钥使用 Cockpit 现有 AES-256-GCM 存储加密，保存在当前应用数据目录的 `cpa-management.enc`。密钥不会经查询接口回传前端，不进入普通配置、账号导出、应用数据导出或日志。加密密钥仍按现有账号存储机制保存在本机；这不是系统 Keychain。整个数据目录的手动备份仍须作为敏感文件保护。

## 上传与自动同步

- 勾选本地账号，点击上传/更新并确认目标。每批最多 100 个；每个账号单独报告结果。
- 默认文件名是本地稳定账号 ID 的 SHA-256：`cockpit-codex-<hash>.json`，不随列表顺序、备注或时间变化。
- 首次 POST 创建文件；已有受管文件用 PATCH `/fields` 只更新认证字段，保留远程禁用、代理、优先级、模型配置。
- 仅支持有可验证有效期的普通 Codex OAuth 凭据；API Key、Agent Identity、Web Session、个人访问令牌及未完成登录账号不上传。
- **永不上传 refresh_token、密码、2FA、手机号或私人备注。** CPA 的 `refresh_token` 会被置空。本地负责刷新；令牌变化后每 60 秒检查一次并发送更新。依赖已有本地令牌刷新/保活机制，不另外竞争刷新链。
- 开启「新账号默认上传」后，只接纳此后新增的合格账号，不自动上传已有历史账号。新增后的登录/导入将在下一轮检查时发现。此开关与已关联账号的令牌更新开关独立。
- **本地应用关闭、断网或令牌刷新停止后，CPA 只能使用到当前 access token 到期。** 如需服务器独立持续刷新，应为 CPA 使用独立登录会话，不能把同一 refresh token 给两端竞争刷新。
- 远程删除、账号读取失败或写入失败后停止对应绑定，需要显式上传恢复。HTTP 401/403 暂停整个连接的自动请求，修正密钥并测试保存后恢复；不会反复尝试触发 CPA IP 封禁。
- 不把存储成功等同于模型调用成功：本功能不替用户调用付费模型验证凭据。

## 已有远程凭据、关联与删除

点击加载/刷新列出服务器已有 **Codex** 凭据（不会操作其他提供商）。没有本地副本也可查看、启停或精确删除文件；`runtime_only` / 内存凭据禁用这些操作。

「关联账号」读取用户明确选定的单个远程凭据，在 Rust 内核对 **account_id 与邮箱**，两者均一致才建立绑定；不会根据相同邮箱自动关联。关联本身不改写凭据，下一次显式上传才清空远程 refresh token 并启动本地托管。一个本地账号/远程文件各只允许一个绑定。

远程删除必须确认；有绑定时可勾选「同时将关联本地账号移入回收站」。顺序为：持久化停止同步 → 精确删除远程文件 → 成功后调用现有本地回收站工作流。远程失败则保留本地；远程成功但本地失败会明确提示部分完成。不会调用 `all=true`。本地原账号页的普通删除仍不连带远程删除；如需一起删除，请从 CPA 管理操作。

所有连接变更、上传、删除、同步使用跨进程文件锁；操作携带连接 ID，拒绝过期界面向另一个服务器发送请求。后台只更新已有文件，缺失不会自行重新创建。第三方管理员同时改动同一凭据的竞争仍受 CPA 接口本身限制（接口没有条件写入/事务保证）。

## 桌面构建

```sh
npm ci
npm run tauri -- build --config src-tauri/tauri.cpa.conf.json
```

需要 Node/npm、Rust、Go 和对应系统 Tauri 构建工具。本 fork 的打包覆盖配置使用独立应用标识与 `Cockpit Tools CPA` 名称，不生成官方 updater 签名产物，并清空官方自动更新地址，避免二次开发版本被上游自动更新覆盖。未配置 Apple Developer 签名/公证；本地产物不是已公证发行版。应用仍沿用 Cockpit 数据目录，验证时应设置独立 `COCKPIT_TOOLS_DATA_DIR`，不要把测试写入真实账号库。

CPA 扩展文案单独注册中英文资源；其他界面语言使用项目已有的英文回退机制，不改变原有 18 语言的翻译文件。

## 测试

```sh
npm run typecheck
npm test
node scripts/check_locales.cjs
cargo test --package cockpit-tools --lib cpa_management -- --test-threads=1
```

Rust HTTP 测试只连接本机伪服务，并用隔离临时数据目录测试加密存储、v8/v0、部分失败、身份关联、默认上传边界和删除防复活。真实 CPA 部署的版本、代理配置和模型实际可用性仍需用户配置自己的服务器后验证。

接口依据：[管理 API v8](https://help.router-for.me/cn/management/apiv8) 与 [v0 兼容 API](https://help.router-for.me/cn/management/api)。
